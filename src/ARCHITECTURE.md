# Architecture and module boundaries

Module map for `src/`. Each line states the boundary rule that the module owns; the
MUST/MUST NOT constraints in [AGENTS.md](../AGENTS.md) cite this file as their source.
The product-level picture (pipeline, environments, scripts) is in the [README](../README.md).
The target product (routes, collections, emails) is specified in [docs/product/](../docs/product/);
where that spec and this file disagree, [docs/product/00-deviations.md](../docs/product/00-deviations.md)
says which wins. Rows below marked "(moves)" change when the owning ticket lands.

## Request and job flow

```
browser ── app/(frontend)/*  ── Payload Local API ──┐
cron ───── app/api/jobs/run ── payload.jobs.queue ──┤── payload.config.ts ── collections/*
                                  │                 │                         │
                    payload/jobs/{tasks,workflows}  │                 db-postgres (Drizzle)
                                  │                 │                         │
                              lib/jobs/*  ── lib/wfs/* (upstream)  ── lib/geo/spatial-queries.ts (PostGIS)
                                  └── lib/notifications/* (email)
```

## Cross-cutting invariants

- Three isolated environments (dev 5432, integration Testcontainers, e2e 5433); tests run only via `pnpm test:*` (see [tests/README.md](../tests/README.md)).
- Change detection is geometry-based today (`geom_hash` = `geomHash()` from `lib/geo/hash.ts`, so a ring that merely starts elsewhere or is wound the other way is not a change); attribute-level detection (`attrHash`) lands with MV-072.
- Anything that spans `app/*` and `payload/*` or `lib/jobs/*` is a cross-component change and needs the L3 (e2e) layer before it is done.
